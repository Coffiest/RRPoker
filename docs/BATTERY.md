# 電池を減らさない設計(オーナー指示・2026-11-16)

「RRPoker を使っているとスマホの充電の減りが早すぎる」という報告から決めた。**どの画面・どの状態でも**この決まりを守る。
新しい画面や部品を作るとき・直すときは、最後にこの表を確かめる。`test/battery.test.ts` がビルドの前(`prebuild`)に一部を自動で検査する。

## なぜ電池が減るのか(小学生向けに言うと)

- スマホは「画面を描き直す」「計算する」「電波で通信する」「音の回路を起こしておく」たびに電池を使う。
- 何も変わっていないのに 1 秒に何十回も描き直したり、見えていない所でずっと計算したりすると、使っていないのに電池が減っていく。

## 決まり

| # | 決まり | どこで |
| --- | --- | --- |
| 1 | **ずっと動き続けるアニメを作らない。** 飾りの動きは数回で止める(`animation: ... 3`)。例外は読み込みの回転、TV/PC のタイマー画面そのもの、押している間・並べ替え中・QR を読んでいる間だけの動き | `test/battery.test.ts` の ALLOW |
| 2 | 動かすのは `transform` と `opacity` だけ。`width`・`height`・`top`・`left`・`box-shadow`・`filter` を動かさない(毎コマ配置や描き直しが走る) | 進み具合のバーは `scaleX` |
| 3 | **画面が隠れている間は止める。** 時計の描き直し・回転する案内・時計合わせの通信は `document.hidden` のとき休む。60 秒隠れたら Firestore の通信も止める | `components/BackgroundSaver.tsx`、`lib/serverClock.ts` |
| 4 | 時計は 1 秒に 1 回、表示が変わる瞬間に合わせて描き直す。`setInterval` は 1 秒より短くしない(テストで検査) | `TimerClient`・`LiveTournamentTimer` |
| 5 | 待つだけの処理は「必要な時刻まで眠る」。毎秒起きて確かめない(例: タイマーの音は残り 11 秒まで眠る) | `lib/timerSounds.ts` |
| 6 | **見えていない埋め込み(iframe)は外す。** タイマー画面の埋め込みは画面に近い間だけ付ける | `components/WhenVisible.tsx` |
| 7 | 縮小・見るだけの埋め込みは、音の装置を作らず点滅もしない(`?embed=1` / `?mute=1` / `view=1`) | `TimerClient` |
| 8 | 音の装置(AudioContext)は鳴らし終えて 4 秒で眠らせる | `lib/timerSounds.ts`・`TimerClient` |
| 9 | Firestore のリアルタイムの見張り(onSnapshot)は、画面に出ていて変わりうるものだけ。たくさんある物(来たことのある人全員など)は 1 回読み、必要なときに読み直す | 店舗ホームの Players |
| 10 | 見張りから届くたびに全部を並べ直さない。まとめて 1 回にする(80ms など) | 店舗ホームの Players |
| 11 | カメラ・重い計算は使う間だけ。QR の読み取りは 0.1 秒に 1 回(毎コマにしない)。閉じたらカメラを止める | `app/components/QRScanner.tsx` |
| 12 | SVG のゆがみ(filter)などの重い効果は、ずっとは動かさない | トップの「今すぐはじめる」 |

## 測り方

エミュレーターで、画面を開いて 15 秒何もしない間の Chrome の `Performance.getMetrics` を比べる(`TaskDuration`・`LayoutCount`・`RecalcStyleCount`)。
2026-11-16 の改善: 7 大会の店舗ホーム 4.69 秒 → 0.42〜0.51 秒(配置 1800 回 → 30 回)、プレイヤーホーム 0.97 秒 → 0.07 秒。
